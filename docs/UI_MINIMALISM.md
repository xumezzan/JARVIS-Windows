# Минималистичный интерфейс Jarvis

15 октября 2026. Упрощение существующего интерфейса без реализации последующих этапов.

## Структура и путь пользователя

- **Ассистент** — одна команда и основная кнопка «Продолжить». Команда переносится в
  существующее окно ассистента для проверки и отдельного запуска. Ctrl+Enter делает тот же
  переход. Голосовой ввод открывает это окно; запись начинается только по удержанию кнопки.
- **История** — ограниченный журнал событий оболочки текущего сеанса. Это не постоянная
  история разговоров и не объединённый журнал всех действий планировщика.
- **Инструменты** — явный вход «Браузер и приложения», сворачиваемые демонстрация интерфейса
  и локальный календарь. У демонстрации собственный ввод, результат и сценарий ошибки.
  Календарь показывает местный месяц без подключения сервиса.
- **Настройки** — оформление (тема и анимация), затем переходы к модели и голосу, памяти
  и Outlook. Оформление действует до закрытия приложения. Открытие раздела не запускает
  модель, микрофон, OAuth или инструменты.

Главная больше не объединяет историю, календарь и приложения в конкурирующие колонки.
На ней остаются небольшая сфера, команда и следующий шаг. Названия разделов соответствуют
реальным экранам; выделение навигации связано с показанным экраном и при системном действии
доступности. При узком окне навигация становится компактной, сохраняя доступные имена.

В окне ассистента вкладки: **Задача → Память → Outlook → Настройки**. Необязательные
параметры провайдера, модели распознавания и озвучивания перенесены в настройки. Перед
запуском видны выбранный провайдер, режим симуляции, а для OpenAI — отдельное согласие
и раскрытие передачи данных даже при симуляции инструментов. Проверка распознанного
текста и отдельный запуск сохранены. Переход с удерживаемой записи на другую вкладку
отменяет запись. Точные одноразовые подтверждения действий не менялись.

Демонстрация может завершиться в фоне, пока открыт другой раздел: она не меняет страницу
и не перехватывает фокус. Кнопка остановки остаётся в общей верхней строке, Escape отменяет
демонстрацию. Черновик команды ассистента и ввод демонстрации независимы.

## Внешний вид

Inter, спокойные тёмные темы Midnight и Graphite, одна основная кнопка, тонкие разделители
вместо многочисленных карточек. Общая тема применяется к оболочке и открытым рабочим окнам.
Сфера сохранена в уменьшенном размере; её движение отключается в настройках.

## Фактическая проверка на macOS

Использовано изолированное окружение `/tmp/jarvis-share-report-venv`: существующая `.venv`
оказалась неработающей ссылкой. Установка `python -m pip install -e ".[dev]"` прошла.

```sh
QT_QPA_PLATFORM=offscreen /tmp/jarvis-share-report-venv/bin/python -m pytest -q
/tmp/jarvis-share-report-venv/bin/python -m ruff check .
/tmp/jarvis-share-report-venv/bin/python -m ruff format --check .
/tmp/jarvis-share-report-venv/bin/python -m mypy
QT_QPA_PLATFORM=offscreen /tmp/jarvis-share-report-venv/bin/python -m jarvis --smoke-test
/tmp/jarvis-share-report-venv/bin/python -m build
```

- **574 passed, 5 skipped**. Пропуски: настоящий Windows (3), живой model API (1),
  реальные микрофон/звук (1).
- Ruff check/format: passed, 156 файлов. Mypy: passed, 120 файлов.
- GUI smoke: `Jarvis GUI smoke: success`. Wheel и sdist собраны.
- Native Cocoa: просмотрены оболочка 1200×820 и 860×640, настройки, задача офлайн/OpenAI
  и параметры ассистента. Интерактивно запущен `python -m jarvis`, проверен переход
  к настройкам через macOS accessibility. Qt-тесты проверяют отсутствие горизонтальной
  прокрутки, независимость ввода, сохранение страницы при завершении демо и перенос
  команды без автоматического выполнения.
- Независимая проверка Qt: переключение вкладки при удерживаемой записи отменяет
  fixture-запись, освобождает recorder и не вставляет устаревший текст.
- React: TypeScript/Vite build passed. Исходный `node_modules` зависал на чтении файлов;
  выполнен `npm ci` с исходным lockfile в идентичной временной копии. Зависимости проекта
  не изменялись. Проверены 1440×900 и 390×844, отдельные страницы, темы, отключение
  движения, валидация, Ctrl/Cmd+Enter, отмена Escape и история. Переполнения и ошибок
  консоли не обнаружено.

Первый полный прогон обнаружил две проверки smoke, использовавшие старое поле ввода;
entrypoint переведён на отдельный демо-ввод. Следующий выявил ожидание прежней формулировки
CLI help; описание уточнено с сохранением явной границы `no command execution` для демо.
Финальный полный прогон прошёл. При проверке accessibility обнаружено переключение
выделения без смены страницы; навигация теперь реагирует на изменение выбора.

Эти результаты не подтверждают Windows, живой Outlook/OAuth, model API или оборудование.
На Windows после установки проверить обе темы, четыре раздела, перенос команды без
автозапуска, переключение вкладок и остановку, затем выполнить команды проекта:

```powershell
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python -m ruff check .
.\.venv\Scripts\python -m ruff format --check .
.\.venv\Scripts\python -m mypy
.\.venv\Scripts\python -m jarvis --smoke-test
.\.venv\Scripts\python -m build
.\.venv\Scripts\python -m jarvis
```

Установка на чистую Windows и реальные acceptance-сценарии по-прежнему требуют
[WINDOWS_ACCEPTANCE.md](WINDOWS_ACCEPTANCE.md); готовность всего MVP не заявляется.
