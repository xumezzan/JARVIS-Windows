# Этап 6 — локальный голос / push-to-talk

Дата: 2026-09-15. Этап реализован локально поверх незакоммиченных изменений этапа 5.
**Настоящий микрофон, качество Vosk, слышимый системный голос, живой OpenAI API и native
Windows ещё не проверены.** Память, внешние сервисы и упаковка относятся к этапам 7–9.

## Что добавлено

- Кнопка микрофона dashboard открывает планировщик без записи. В планировщике — выбор
  папки русской модели, удержание мыши/пробела, индикатор записи и отключённое по умолчанию
  озвучивание результата. Библиотеки голоса устанавливаются через необязательный `.[voice]`.
- LocalRecorder (sounddevice / PCM 16 kHz int16 mono), VoskRecognizer с явным model_path
  и LocalSpeaker (sapi5/nsss/espeak). Нет автоматической загрузки моделей/голосов, облачного
  STT/TTS, аудиофайлов, новых credentials или фонового прослушивания.
- Сменные Recorder/Recognizer/Speaker и детерминированные fixtures. Native libraries
  запускаются в отдельных killable helpers через ограниченный stdin/stdout pipe.
  Содержимое не передаётся через argv, исключения ограничены конечными категориями.
- Запись до 30 секунд / 960 000 bytes. Recording transport — 35 секунд, STT — 45,
  TTS — 25, capture+STT — 80; весь голосовой сеанс с просмотром текста/планом — 5 минут.
  Лимиты Runner и каждого approval сохраняются. Повторы не выполняются автоматически.
- Расшифровка попадает в редактируемую команду; только отдельное нажатие запуска вызывает
  прежний Runner/PermissionEngine. Тишина отклоняется, низкая уверенность явно отмечается.
  Уверенность — эвристика Vosk (минимальный word confidence, порог 0.75), не гарантия качества.
- В процессе задачи точные «стоп», «отмена», «отмени», «остановись», «остановить»,
  «отмени задачу» отменяют её при активной записи. Другая речь не заменяет текущую команду.
  «Подтверждаю» не выдаёт approval. В модальных диалогах есть push-to-talk, индикатор,
  Stop; Escape отменяет голосовую работу и весь план.
- Потеря фокуса/скрытие удерживаемой кнопки, Stop/Escape/закрытие отменяют работу и
  исключают позднюю расшифровку. Запись не запускается во время TTS; для новой записи
  сначала остановить речь и заново удерживать кнопку. Нет TTS-to-STT автопетли.
- Озвучивается короткий текст из статусов engine и количества проверенных SUCCESS,
  без raw results, model text, имён инструментов или аргументов. При ошибке/отмене
  возможные уже выполненные эффекты не объявляются отозванными.

## Windows 11: установка и запуск

Из актуальной копии исходников, после установки Python 3.12 x64 и Git:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,voice]"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m jarvis --smoke-test
.\.venv\Scripts\python.exe -m jarvis
```

Скачайте и распакуйте русскую модель из [официального списка Vosk](https://alphacephei.com/vosk/models),
например `vosk-model-small-ru-0.22`. Выбирайте папку, содержащую `am/final.mdl`, а не ZIP
или родительский каталог. Для системного озвучивания нужен установленный русский голос.

Первый сценарий: открыть планировщик → выбрать модель → удерживать кнопку до индикатора
«Идёт запись» → сказать «проверь систему дважды» → отпустить → проверить/исправить текст
→ запустить → увидеть два SIMULATED. Затем снять simulation и повторить локальные проверки.
Для Блокнота следует вручную проверить кавычки и текст: офлайн-планировщик понимает учебные
шаблоны, Vosk не гарантирует пунктуацию. Произвольные формулировки требуют отдельного LLM.

Аппаратный тест требует настоящего рабочего стола и ручного удержания кнопки:

```powershell
$env:QT_QPA_PLATFORM = "windows"
$env:JARVIS_VOSK_MODEL = Read-Host "Папка локальной русской модели Vosk"
.\.venv\Scripts\python.exe -m pytest tests/e2e/test_voice_acceptance.py --run-voice -v -s
Remove-Item Env:QT_QPA_PLATFORM
Remove-Item Env:JARVIS_VOSK_MODEL
```

Тест даёт 90 секунд на запись, проверку и запуск. Он ожидает два SIMULATED и callback
завершения TTS; слышимость/разборчивость звука пользователь проверяет отдельно.
Приёмка отказов микрофона, тишины, отмены в каждой фазе, CONFIRM-ввода в пустой Блокнот,
DPI, закрытия и повторного открытия приведена в [TESTING.md](TESTING.md).

## Ограничения

- Windows 11 / Python 3.12 совместимость voice dependencies, устройства и русской модели
  ещё требует приёмки. Установка библиотек на macOS не доказывает работу на Windows.
- 16 kHz mono должен поддерживаться устройством ввода ОС. Автоматического ресэмплинга,
  выбора другого устройства или смены драйвера после ошибки нет.
- Отмена речью работает после отпускания кнопки и локального распознавания. Для мгновенной
  остановки используйте Stop/Escape. Во время TTS запись запрещена; Stop доступен.
- Модель загружается в новом helper для каждого распознавания; это добавляет задержку.
- Аудио не передаётся в облако. Если отдельно выбран OpenAI-планировщик, проверенный текст
  и наблюдения могут передаваться только после существующего UI disclosure/consent.
- Аудио/транскрипт не сохраняются в приложении; гарантии стирания RAM/swap/OS crash dumps нет.
- Для Windows используйте опубликованную ветку `codex/milestone-5-planner`: она включает
  этапы 5–6 и обновлённый дизайн. Проверка публикации выполняется сравнением remote SHA.
