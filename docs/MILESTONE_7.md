# Этап 7 — управляемая память

Дата: 2026-09-15. Реализован локально на macOS / Python 3.12.7.
Windows, реальный OpenAI API и настоящее голосовое оборудование остаются непроверенными.
Внешние сервисы и установщик относятся к этапам 8–9.

## Использование

Откройте планировщик с dashboard, затем вкладку **Память**.

1. Выберите категорию, введите короткую метку и значение. Для контакта это имя и роль,
   для приложения — Notepad, Chrome или VS Code из списка.
2. **Сохранить в профиль** явно записывает данные локально. Для изменения выберите строку,
   измените поля и сохраните. **Новая запись** сбрасывает выбор редактирования.
3. **Удалить запись**, **Очистить профиль** и **Перечитать** управляют сохранёнными данными.
   Удаление окончательное для приложения, без своей корзины.
4. **Добавить в контекст** добавляет введённую метку только в текущий сеанс. Отдельные
   кнопки удаляют выбранную метку и сбрасывают весь контекст.
5. Отметьте нужные строки галочками. Предпросмотр показывает все значения следующей задачи.
   Выбор расходуется одним запуском; содержание профиля и неистёкшего сеанса остаётся доступно.
6. В офлайн-режиме с одной выбранной меткой приложения команда **«открой выбранное приложение»**
   заново вызывает `windows.open_app`. При нескольких приложениях нужно уточнение.
   **«открой chrome»**, **«открой vs code»** и прежние учебные рецепты поддерживаются.
7. Для OpenAI нужны прежнее согласие на передачу команды/наблюдений и отдельная галочка
   передачи **показанных меток для одной задачи**. Изменение выбора или профиля снимает её.
   Пустой выбор не требует отдельного согласия на память. Simulation не отключает вызов LLM.

Это короткий контекст разговора из явно введённых меток, а не архив переписки. Команды,
расшифровки, уточнения, файлы, результаты инструментов и страницы не извлекаются в память.
Предыдущий выбранный редактор можно явно оставить меткой сеанса и выбрать для следующей
задачи. Автоматического сохранения истории или скрытого профилирования нет.

## Хранение и границы

- `memory.sqlite3` находится рядом с `audit.sqlite3` в `AppConfig.data_dir`.
  По умолчанию Windows: `%LOCALAPPDATA%\Jarvis`, macOS: `~/Library/Application Support/Jarvis`.
- Профиль: до 32 записей, по 80 символов на метку и значение, срок до 30 дней с сохранения.
  Контекст: до 6 меток, 30 минут по монотонным часам, сброс при закрытии планировщика.
  В одну задачу входят максимум 8 записей профиля и 6 меток контекста.
- Pydantic strict/frozen/extra-forbid, повторная валидация при чтении и сохранении.
  Разрешены только обычные короткие метки. Адреса, URL, JSON, переносы строк, длинные
  непрерывные идентификаторы и известные обозначения credentials/approval/target запрещены.
  Приложения ограничены enum; HWND, PID, DOM, snapshots и approval не имеют полей хранения.
- Ограничение меток и фильтр **не определяют смысл любого произвольного текста**: короткое
  слово может оказаться чьим-то паролем. Не вводите секреты или чувствительные сведения.
  Нет доступа памяти к credential backend, автоматического чтения секретов или обещания
  универсального DLP. Профиль не шифруется; он предназначен для обычных несекретных меток.
- SQLite-транзакции, сравнение предыдущей версии при редактировании/удалении, busy timeout
  1 секунда, bounded reads, отказ для файла больше 1 MiB и для symlink. `secure_delete=ON`,
  rollback journal DELETE. Не создаются пользовательские backups или текстовые журналы памяти.
- I/O выполняется в QThread; cancellation проверяется до работы и перед commit, а также
  progress handler SQLite. Отмена после commit не откатывает сохранённый факт. После отмены
  или конфликта используйте **Перечитать**. Это не hard timeout для зависшей файловой системы ОС.
- Истёкшие записи исключаются из нового снимка сразу. Физическая очистка выполняется при
  чтении/изменении хранилища и минутной проверке открытой незанятой панели. Когда приложение
  закрыто, фоновой очистки нет. Уже запущенная задача держит свой неизменяемый снимок до
  завершения/отмены, максимум по существующему лимиту Runner (180 секунд по умолчанию).
- Ошибка чтения не превращается в пустой «успешно загруженный» профиль: видна конечная
  категория отказа. Некорректные строки можно очистить кнопкой. Повреждённый сам SQLite-файл
  не перезаписывается автоматически: закройте приложение, восстановите файл самостоятельно
  или явно удалите только `memory.sqlite3`, если согласны потерять профиль, затем откройте снова.
  Изменения из другого процесса перечитываются кнопкой; уже переданный снимок нельзя отозвать
  удалением записи, для остановки задачи используйте Stop.
- Гарантий стирания из RAM, swap, системных backups, filesystem journal или SSD нет.

## Планировщик и безопасность

Память передаётся отдельным `untrusted_memory`, только как `kind/label/value`; ID и время
хранения не отправляются. Метки не добавляются в system instructions или tool schemas.
OpenAI получает только выбранный снимок после UI disclosure, offline не обращается к сети.
Runner освобождает свой снимок после завершения задачи.

Выбранные контакты и соответствующая ссылка/команда сообщения вызывают детерминированное
уточнение до запроса провайдера. Существующий лимит вопросов, общий timeout и Stop действуют
и здесь. Офлайн-провайдер также просит уточнение для сообщений; внешняя отправка недоступна.
Это консервативное распознавание ссылок, не полноценный русский морфологический анализ.
Даже однозначная роль не определяет точного адресата и не выдаёт разрешение на запись.

Все tool calls по-прежнему проходят registry → PermissionEngine. Память не получает
approval authority. CONFIRM, CRITICAL/BLOCKED, audit до adapters и simulation сохранены.
Windows/browser targets принимаются только из SUCCESS наблюдений **текущей** задачи.
Голос по-прежнему требует review и отдельного запуска; запись, озвучивание и отмена не менялись.

Использовано существующее изолированное `.venv`, повторная установка `.[dev]` успешна.
Новых зависимостей и pins нет. Проверки не обращались к OpenAI, credentials или микрофону.

Пять пропусков: 3 Windows acceptance, 1 live OpenAI, 1 voice hardware.

Проверены persistence/restart/edit/delete/clear, TTL, лимиты, malformed/oversized storage,
конфликт редактирования, SQLite lock, отмена до commit с rollback, явный выбор контекста,
prompt injection как данные, невозможность выдать approval, контакты, запрет старых targets
в simulation и execute, отсутствие автоматического сохранения текста/речи, cloud disclosure,
сброс выбора и согласия после задачи, закрытие сеанса. Общие regression tests проверяют
прежние browser/voice/PermissionEngine сценарии.

`python -m jarvis` запускался с `QT_QPA_PLATFORM=cocoa` и отдельным тестовым data directory.
Интерактивная проверка через computer-use не завершена: инструмент вернул `timeoutReached`
и `noWindowsAvailable`. Это ограничение указано отдельно от успешных native Qt-тестов и smoke.
Qt-render панели осмотрен при 900×790 и компактном размере: наследует палитру приложения,
форма имеет прокрутку, скрывает неактуальные поля, галочки выбора читаемы.

## Windows 11: точные команды приёмки

Это команды разработчика для текущего этапа. Автоматическая установка без подготовки Python
будет реализована только на этапе 9.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,voice]"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m mypy
$env:QT_QPA_PLATFORM = "windows"
.\.venv\Scripts\python.exe -m pytest tests/integration/test_memory_ui.py tests/integration/test_planner_ui.py tests/integration/test_voice_ui.py -q
.\.venv\Scripts\python.exe -m jarvis --smoke-test
.\.venv\Scripts\python.exe -m jarvis
.\.venv\Scripts\python.exe -m pytest tests/e2e/test_windows_acceptance.py --run-windows -v -s
Remove-Item Env:QT_QPA_PLATFORM
.\.venv\Scripts\python.exe -m build
```

В живом окне проверьте:

1. Сохранить несекретный проект, закрыть/открыть приложение, изменить, удалить и очистить.
2. Добавить Блокнот в контекст, отметить, выполнить «открой выбранное приложение» в simulation,
   затем заново отметить и повторить в execute. Проверить реальное окно и новое наблюдение.
3. Добавить Chrome и отметить оба приложения: получить уточнение, затем отменить через Stop.
4. Добавить двух «Саша» с разными ролями, выбрать обе записи, написать «напиши Саше»:
   уточнение, без отправки. Не считать ответ на уточнение approval.
5. Выбрать OpenAI и память без отдельного согласия: запуск блокируется. Без настройки ключа
   не включать живой запрос. Live-model/voice приёмка остаётся по `MILESTONE_5.md`/`MILESTONE_6.md`.
6. Проверить прокрутку, клавиатуру, DPI 100/150/200%, отмену/закрытие во время операции памяти,
   недоступный профиль и отсутствие меток сеанса после закрытия планировщика.
