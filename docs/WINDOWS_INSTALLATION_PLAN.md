# Установка на другом Windows-ноутбуке — требование к этапу 9

Пожелание пользователя, 2026-09-15: разработка продолжается на Mac. На целевом ноутбуке
пользователь получает репозиторий, открывает его в Codex и пишет:

> Установи Jarvis на этот ноутбук и проверь, что он запускается.

После этого подготовка окружения, установка и проверка запуска должны выполняться
автоматизированным сценарием из репозитория. Пользователю не нужно вручную собирать
команды pip, настраивать PATH или разбираться в зависимостях.

**Это требования к установке.** Переносимая реализация этапа 9 подготовлена:
`scripts/windows/Install-Jarvis.cmd`. Реальная установка на Windows ещё не проверена.
Фактические результаты и ограничения: [MILESTONE_9.md](MILESTONE_9.md).
Приёмка: [WINDOWS_ACCEPTANCE.md](WINDOWS_ACCEPTANCE.md).

## Требуемое поведение

1. Репозиторий содержит однозначную инструкцию для агента и один проверенный сценарий
   установки для Windows 11 x64. Он проверяет ОС, архитектуру, доступность сети,
   права и наличие необходимых компонентов до изменений.
2. Установка обеспечивает подходящий Python/runtime, изолированные зависимости,
   браузерный Chromium, локальную русскую модель распознавания и доступность озвучивания.
   Пользователю не требуется заранее вручную устанавливать Python. Выбор механизма
   (готовая Windows-сборка или bootstrap окружения) проверяется на целевой Windows.
3. Загружаемые компоненты берутся из официальных источников с проверкой целостности
   и совместимости. Модель загружается установщиком в явно выбранной конфигурации;
   обычный запуск Jarvis не начинает фоновые загрузки или запись микрофона.
4. По возможности установка выполняется для текущего пользователя. Повторный запуск
   проверяет и восстанавливает недостающие компоненты, сохраняет настройки и данные,
   не создаёт дубликаты окружений/ярлыков и не сбрасывает учётные данные.
5. После установки доступен обычный запуск Jarvis через ярлык. Зависимости разработки,
   локальные инструменты дизайна и React-превью не нужны для работы приложения.
6. Сценарий проверяет установленную версию, зависимости и GUI smoke, затем запускает
   приложение. При ошибке сообщает конкретную причину и следующий шаг; не объявляет
   установку успешной только потому, что выполнил команды.
7. Локальный режим доступен без API-ключа. Ввод ключей и OAuth-вход для облачных функций
   выполняет пользователь через безопасный setup; секреты не копируются с Mac,
   не передаются в чат и не сохраняются в репозитории или env-файлах.
8. Обязательные системные диалоги, разрешение микрофона и подтверждения подключения
   сервисов остаются явными действиями пользователя. Автоматизация не обходит их.

## Критерии приёмки

- На чистой Windows 11 x64 после получения репозитория агент выполняет установку
  по одному пользовательскому запросу без ручной подготовки Python/зависимостей.
- Проверены первый и повторный запуск установки, путь с пробелами/кириллицей,
  отсутствие сети, прерванная загрузка, отсутствие прав и восстановление после сбоя.
- Приложение запускается из ярлыка; локальные команды, Chromium и русский голос
  проходят отдельные реальные проверки. Микрофон проверяется только явным удержанием.
- Зафиксированы Windows build, версии компонентов, результаты и оставшиеся ограничения.
  Тесты на Mac не заменяют эту приёмку; финальная готовность подтверждается на Windows.

Порядок работ: этап 7 (память) → этап 8 (внешний сервис) → этап 9 (Windows-приёмка,
упаковка и установка по одному запросу). Ранние проверки на Windows допустимы и полезны.
