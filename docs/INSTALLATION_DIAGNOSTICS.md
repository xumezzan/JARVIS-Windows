# Автоматическая диагностика при установке

Добавлено 2026-10-14 в рамках этапа 9. Реальная Windows-приёмка остаётся открытой.
Итоговый документ для отправки добавлен 2026-10-15; это расширение диагностики этапа 9.

## Запуск и файлы

На Windows 11 x64 из полной копии репозитория:

> Установи Jarvis, выполни доступные проверки и покажи итоговый Jarvis-Report.html для отправки.

```powershell
& '.\scripts\windows\Install-Jarvis.cmd'
$jarvisInstallExit = $LASTEXITCODE
Get-Content -Encoding UTF8 -LiteralPath "$env:LOCALAPPDATA\JarvisInstall\Jarvis-Report.md"
Get-Content -Encoding UTF8 -LiteralPath "$env:LOCALAPPDATA\JarvisInstall\installation-bootstrap.md"
Get-Content -Encoding UTF8 -LiteralPath "$env:LOCALAPPDATA\JarvisInstall\installation-report.md"
if ($jarvisInstallExit -ne 0) { throw 'Installation did not pass; inspect current reports' }
```

Python/pip вручную не готовятся. Эти же команды повторяют проверку и восстанавливают
компоненты; при совпадении исходников и сохранённых хэшей загрузок нет.

- `Jarvis-Report.html`: единый русскоязычный документ UTF-8, открываемый в обычном браузере,
  без внешних ресурсов. Содержит итог установки, матрицу возможностей, фактические результаты,
  ошибки, границы доказательства и следующие шаги.
- `Jarvis-Report.md`: текстовая копия того же итогового документа.
- `installation-bootstrap.md` и `.json`: Windows/session, безопасный каталог и lock,
  официальный runtime, запуск установщика приложения, создание launcher/ярлыка.
- `installation-report.md` и `.json`: компоненты, локальные функциональные проверки,
  интерфейс, показ настоящего окна и активация слота; отдельный список ручной приёмки.

Для разбора в чате отправьте **только `Jarvis-Report.html` или `Jarvis-Report.md`**.
Журналы, архив каталога установки, аккаунтные данные и credentials для этого не нужны.
HTML можно сохранить и переслать как один файл; интернет для его просмотра не требуется.

Исходные Markdown предназначены для человека, JSON schema 2 — для диагностики и дальнейшей
обработки. В файлах есть время UTC, идентификатор попытки `run_id`, статус каждой проверки,
граница её доказательства, категория ошибки и следующий шаг. Итоговый документ объединяет
**только одинаковые run_id** bootstrap и приложения. Если приложение не дошло до своего
отчёта, его результаты остаются непроверенными; старый файл не дополняет новую попытку.

До получения exclusive lock и проверки владельца каталога bootstrap пишет отчёт в новый
каталог `%TEMP%\JarvisInstallReport-<случайный ID>` и показывает точный путь в консоли.
Это относится к неподдерживаемой ОС, блокировке другим установщиком и небезопасным путям.
Ошибка сохранения основного bootstrap-отчёта также вызывает попытку временного отчёта.
В этом каталоге итоговые `Jarvis-Report.html` и `.md` также описывают текущую попытку.
Читать и отправлять нужно напечатанный путь, а не старый документ основного каталога.
Если сохранить документ не удалось, консоль явно сообщает об этом.

## Что проверяется автоматически

1. Runtime и подготовка компонентов; размер/хэш reviewed assets и Windows Authenticode
   Python сохраняют действующие проверки. Upstream browser archive integrity и Windows
   dependency lock остаются отдельными незакрытыми release gates этапа 9.
2. `pip check` и отдельный импорт каждого runtime-модуля, включая native зависимости.
3. Запуск настоящего Chromium, чтение локальной страницы без сети и JavaScript.
4. Загрузка локальной русской Vosk-модели без записи или распознавания микрофона.
5. Реальный PermissionEngine на фиксированных локальных инструментах: SAFE outcome,
   CONFIRM без approval отклоняется, CRITICAL/BLOCKED не выполняются, симуляция не вызывает
   adapter hooks, отмена не вызывает эффекта; временный аудит читается после повторного открытия.
6. Реальный офлайн Runner: два проверенных `local.check` через PermissionEngine.
7. Создание, повторное чтение, изменение, удаление и очистка синтетической памяти
   во временной SQLite. Пользовательская память не открывается.
8. Создание явного OS credential backend **без get/set/delete**. Это подтверждает
   возможность построить backend, а не доступность реальных секретов или работоспособность store.
9. Перечисление устройств ввода/вывода и русского SAPI5-голоса без записи и озвучивания.
10. Версии разрешённого списка runtime-пакетов, native GUI demo smoke во временных данных,
    свежая PID-bound квитанция видимого Windows Qt-окна и активация проверенного слота.
11. Политика браузера через PermissionEngine: недопустимые URL/POST отклоняются,
    SAFE-симуляция не вызывает backend. Это проверка без запуска браузера и сети.
12. Синтетический Outlook RAM-черновик через PermissionEngine: создание, чтение и очистка;
    удалённый черновик и отправка без approval отклоняются. OAuth/credentials/Graph не вызываются.

Компоненты проверяются независимыми дочерними процессами. Timeout отдельной проверки
ограничен 15 секундами, Chromium/model/pip/GUI — 30 секундами; при timeout helper завершается.
Ошибка одного импорта не скрывает результаты остальных проверок. Обязательная ошибка
или отсутствующий обязательный результат запрещают запуск/активацию кандидата.
Отсутствующие аудиоустройства/русский голос требуют настройки; текстовый режим может работать.

## Матрица текущих возможностей в итоговом документе

Документ отделяет функциональную проверку от обнаружения компонента. Вся строка функции
не становится успешной из-за импорта библиотеки или найденного устройства.

| Возможность | Доступная автоматическая проверка | Что остаётся непроверенным |
| --- | --- | --- |
| Установка и запуск | Подготовка runtime/пакетов, создание launcher/ярлыка, native GUI smoke, квитанция видимого окна | Чистая Windows, повтор без сети, реальный запуск из «Пуск» и сценарии отказов |
| Разрешения и аудит | Реальные ограниченные локальные проверки PermissionEngine, симуляции, отмены и временного аудита | Точный UI approval и исходы реальных внешних действий |
| Планировщик команд | Реальный офлайн Runner выполняет два `local.check` | Произвольные пользовательские сценарии и облачный провайдер |
| Память | Запись, чтение, изменение, удаление и очистка синтетической базы | Пользовательский сценарий выбора меток и передачи с отдельным согласием |
| Windows-приложения | Загрузка adapter dependencies | Открытие/фокус Notepad, Chrome, VS Code; ввод с точным approval и UIA read-back |
| Браузер | Реальный Chromium читает локальную страницу без сети и JavaScript; отдельно проверены политика и симуляция через PermissionEngine | Публичная выдача, реальные навигация/формы и точные подтверждения |
| Распознавание речи | Загрузка локальной Vosk-модели и обнаружение микрофона | Разрешение ОС, удержание кнопки, запись, transcript review, распознавание и отмена |
| Локальное озвучивание | Импорт TTS, обнаружение выхода и русского SAPI5-голоса | Слышимый звук, качество и остановка озвучивания |
| Системные credentials | Создание явного native backend без чтения/записи секретов | Реальная работа credential store и доступ выбранного аккаунта |
| Outlook | Библиотеки и синтетический RAM-черновик через PermissionEngine без подключения; запрет удалённых действий без approval | OAuth/MFA, чтение живых писем, удалённый черновик, точный approval отправки, accepted и фактическое получение |
| Облачная модель OpenAI | Загрузка библиотек без сетевого вызова | UI disclosure, пользовательский ключ, выбранная модель и реальный ответ API |
| Необязательный ElevenLabs | Установка общих runtime-зависимостей | Ключ, одноразовое согласие, Free/квота и слышимый результат |

Ручные строки автоматически остаются **НЕ ПРОВЕРЕНО**. Установщик не выполняет вход,
не держит за пользователя кнопку микрофона и не создаёт approvals. Документ не выдаёт
отсутствие результата за ошибку функции и не приписывает ручным проверкам успех.

## Значение результатов

| Статус | Значение |
| --- | --- |
| ПРОЙДЕНО | Получено указанное в строке доказательство этой ограниченной проверки |
| ОШИБКА | Проверка завершилась с фиксированной категорией ошибки; прочитайте следующий шаг |
| НУЖНА НАСТРОЙКА | Необязательное устройство/голос отсутствует либо обнаружение не удалось |
| НЕ ПРОВЕРЕНО | Результат не получен или нужно действие пользователя; это не успех |
| ПРОВЕРЯЕТСЯ | Проверка начата, завершённый результат ещё не сохранён |
| ОТМЕНЕНО | Установка или текущая проверка отменена |

Общий `automatic_checks_passed` относится только к автоматической диагностике приложения.
Он не означает полную приёмку MVP и не подтверждает ярлык: его создание записано отдельно
в bootstrap; настоящий повторный запуск из «Пуск» требует наблюдения.

Исходные отчёты обновляются по ходу установки; итоговые HTML и Markdown формируются
после успеха, ошибки или обычной отмены. Сбой подготовки/проверки/запуска/активации
и обычная отмена сохраняют соответствующий результат. Непроверенные этапы не становятся
успешными. При ошибке до активации указатель предыдущей установки остаётся прежним;
данные и credentials находятся вне слотов. Сбой отчёта после уже выполненной активации
не означает автоматического отката — нужно проверить указатель и оба отчёта.

Нельзя гарантировать файл, если системная политика не позволяет самому скрипту запуститься,
каталог/временное хранилище недоступны или процесс принудительно убит. После аварийного
завершения последний статус `running` означает незавершённую проверку.

## Что требует участия пользователя

Реальный микрофон/распознавание/слышимый звук, Notepad approval и UIA read-back,
фактическая публичная выдача, запуск из ярлыка, live модель, Outlook OAuth/черновик/отправка
и доставка, optional ElevenLabs, clean/offline/repeated install и полный Windows E2E.
Обнаружение компонентов не закрывает эти проверки. Следовать
[WINDOWS_ACCEPTANCE.md](WINDOWS_ACCEPTANCE.md), сохраняя обычные OS consent и точные UI approvals.

Автоматическая диагностика не читает аккаунты или secrets, не записывает звук,
не отправляет сообщения и не обращается к живому model API. В отчёты не попадают
raw stdout/stderr, исключения, transcript, тела писем или пользовательские данные.
Используются только фиксированные категории/подсказки и разрешённая metadata версий.
Итоговый документ также не встраивает журналы, содержимое файлов или аккаунтов.

Developer full pytest/Ruff/mypy/build остаются в `Test-Jarvis.ps1` и выполняются отдельно:
обычная установка не ставит dev dependencies. Самодиагностика не доказывает отсутствие
всех возможных ошибок приложения.
