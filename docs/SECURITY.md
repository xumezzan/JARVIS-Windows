# Модель безопасности

Этапы 2–4 реализуют PermissionEngine, exact approvals, SQLite audit и Windows-адаптер
в отдельном процессе. Текстовые команды не интерпретируются моделью. Credential adapters, OAuth и внешняя отправка отсутствуют. Native Windows-приёмка ещё не выполнена.

Shell log и tool audit исключают raw arguments, recipient/content, result payload,
exception text и approval tokens. Это ограничение текущего интерфейса журналирования,
а не универсальная redaction для будущих SDK. Микрофон отключён.

## Активы и границы доверия

Защищаются учётные данные, личные документы, содержимое писем, право отправки и целостность
результатов. Пользовательский UI-event отделён от вывода модели. Модель, страницы, письма,
документы и tool results не могут выдавать approval или менять risk policy.
Компрометация ОС или процесса не покрывается защитой от prompt injection; Python-модули
сами по себе не являются sandbox для вредоносного локального кода.

| Угроза | Обязательная защита | Проверка |
| --- | --- | --- |
| Инструкция в письме/странице | Содержимое остаётся данными; registry/policy вне модели | Внешний текст не меняет правила и не даёт согласие |
| Подмена получателя/контента | Immutable нормализованный снимок для preview и execute | Любое изменение требует нового approval |
| Replay или параллельное использование | Короткий срок жизни, атомарное single-use потребление | Из двух одновременных попыток проходит максимум одна |
| Утечка секретов | OS credential store, redaction, ограничение контекста | В логах и prompt нет raw tokens/cookies/credentials |
| Ошибочная речь | Transcript до запуска, risk policy после STT | Ошибочно распознанная отправка всё равно требует approval |
| Повтор после сетевого сбоя | Idempotency и сверка фактического состояния | Не дублировать неопределённую отправку |
| Обход через универсальный tool | Allowlist и оценка фактического действия | Browser click/Enter не обходят подтверждение отправки |

## Risk policy

- SAFE: чтение или обратимое локальное действие в разрешённых границах. Открытие
  приложения и поиск проходят policy check даже без интерактивного подтверждения.
- CONFIRM: отправка, публикация и потенциально разрушительные действия. Нужен approval.
- CRITICAL: установка, безвозвратное удаление, безопасность и credentials; отключено в MVP.
- BLOCKED: переводы, раскрытие секретов, отключение защиты, скрытое наблюдение; отказ всегда.

Неизвестный инструмент, неверная схема или недоказанные preconditions отклоняются.
Risk нельзя понизить по предложению модели. Навигация, generic click, ввод текста и
другие составные действия должны учитывать target и реальный эффект. Неизвестную
внешнюю отправку запрещать, пока adapter не умеет показать и связать точный payload.

## Реализованный approval protocol

1. Валидировать и нормализовать аргументы один раз; создать immutable snapshot.
2. Связать с tool, action type, service, account, target/recipient, subject, body,
   attachments (включая идентичность содержимого), request и режимом исполнения.
3. Показать полный снимок, risk, Cancel и Approve. Модель не имеет инструмента выдачи token.
4. Только trusted UI-event после просмотра выдаёт непредсказуемый короткоживущий token.
   Начальное проектное значение TTL — 60 секунд по монотонным часам.
5. Непосредственно перед исполнением повторно проверить preconditions и атомарно
   потребить token. Исполнять ровно этот снимок; повторное разрешение alias не допускается.
6. Изменение, timeout, cancellation, reuse, смена аккаунта или режима инвалидируют approval.
7. Аудировать факт выдачи/отказа/потребления по безопасному ID, без bearer token.

## Simulation, отмена и журнал

Simulation проходит тот же registry, schema и permission path; adapter hooks, включая
preconditions и verification, не вызываются. Проверка фактической выполнимости в simulation
не заявляется. CONFIRM не становится
SAFE в simulation. Реальный adapter вообще не вызывается; итог маркируется SIMULATED,
а не SUCCESS. Simulation approval нельзя перенести в реальный режим.

Stop запрещает запуск новых шагов, отменяет незавершённые approvals и передаёт сигнал
adapter. Timeout не означает, что удалённая сторона ничего не сделала: не утверждать
откат или успех без проверки. Результаты и duration отражают наблюдаемые факты.

## Секреты и личные данные

Никаких plaintext passwords в source, fixtures, docs, JSON, `.env`, SQLite или prompt.
OAuth с минимальными scopes, explicit connect/disconnect, keyring с Windows Credential
Manager. При недоступном backend безопасно отказывать, без fallback в plaintext.
Не передавать модели tokens/cookies или содержимое всего профиля браузера.

Redaction применяется до хранения и отправки событий в UI/LLM; исключения SDK могут
содержать чувствительные данные, поэтому raw exception/HTTP dumps не логируются.
Audit хранит минимальные metadata, а не все тексты писем. Память доступна пользователю
для просмотра, редактирования и удаления. Микрофон работает только с видимым индикатором.

## Практические границы этапа 2

Authority — capability trusted UI composition, недоступный через tool schemas. Любой код
внутри скомпрометированного Python-процесса всё ещё способен напрямую вызвать callable:
этот прототип защищает границу планов/данных, а не вредоносный локальный код.

Запросы ограничены по количеству и размеру; worker использует кооперативную asyncio cancellation.
Инструменты не должны блокировать event loop или подавлять отмену. Timeout/cancel после
старта adapter помечается возможным эффектом, без обещания отката. После записи эффекта
сбой audit возвращает ERROR, и request повторно не исполняется.

Preconditions обязаны быть side-effect-free. Для настоящих файлов, UIA и сетевых операций
нужны дополнительные adapter-specific invariants; тестовый in-memory outbox их не доказывает.
Attachment signature сейчас связывает metadata, а не выполняет чтение/проверку настоящего файла.

## Windows-граница этапа 3

- Все четыре Windows-инструмента регистрируются до seal и проходят PermissionEngine.
  Simulation не создаёт helper и не вызывает UIA даже для discovery/preconditions.
- Выполнение допускает только известные пути Notepad/Chrome/VS Code; подмена имени файла
  в другом каталоге не добавляет приложение в allowlist. Установка со своими путями
  сейчас не поддерживается. Защита от замены бинарника доверенным локальным пользователем
  или от скомпрометированного приложения не заявляется.
- Ввод только CONFIRM в наблюдённый пустой Notepad. Снимок связывает process identity,
  окно, редактор, выбранную вкладку, service/action_type и буквальный текст. Нет global
  keys, shell, clipboard, Enter/submit и ввода в Chrome/VS Code.
- UIA/native calls живут в killable helper. При отмене ожидается завершение helper,
  но запущенное приложение и уже выданное сообщение ОС не откатываются. Retry отсутствует.
- Нет автоматического закрытия, сохранения, очистки или замены существующего документа.
  Непустой/изменённый target отклоняется. Между проверкой пустоты и доставкой сообщения
  нет атомарной транзакции: одновременное ручное редактирование остаётся ограничением.
- Заголовки окон — недоверенный текст, отображаемый буквально. Payload передаётся в
  UTF-8 по stdin и не попадает в argv, файлы или audit; raw native exceptions подавляются.
- Запуск разрешённого приложения может вызвать его собственную сеть, расширения или
  восстановление сессии. Helper не является sandbox для этого приложения.

## Браузерная граница этапа 4

- Любой сетевой переход, поиск, ввод, клик и закрытие вкладки — CONFIRM. SAFE чтение
  не делает HTTP requests. Симуляция проверяет static URL/risk/schema policy без DNS,
  browser hooks или запуска процесса. Проверка DNS/доступности возможна только реально.
- Разрешаются точные HTTPS origins. Нет wildcard/subdomain inheritance. Userinfo,
  небезопасные schemes, fragments, malformed authority, локальные/private/link-local/
  multicast/reserved адреса запрещены. Все DNS answers проверяются перед передачей
  connector; mixed public/private набор отклоняется целиком, второго unchecked lookup нет.
- Конструкторная test capability разрешает один loopback origin; POST только `/submit`.
  Она отсутствует в tool schema, переменных окружения и production UI. Production POST
  запрещён независимо от подписи кнопки и approval: семантика внешних изменений неизвестна.
  Добавление реальной отправки требует отдельного adapter и deterministic risk policy.
- Контекст анонимный, offline и без page JavaScript. Фиксированный repo-owned DOM inspector
  не принимает код/selector из страницы или будущей модели. Page content — untrusted data.
  CSP, запрет служебных workers, frames, subresources, popup и downloads исключают обход
  подтверждения через обычный page script. Это ограничивает поддержку динамических сайтов.
- HTTP разрешён лишь для exact main-document grant, потребляемого перед сетью. URL/method/body
  сравниваются буквально после нормализации; поля формы дополнительно показаны читаемо.
  Полный DOM/form snapshot проверяется до действия и после него. Изменение требует нового
  чтения и нового approval. Никаких глобальных клавиш, Enter, clipboard или JS execution tools.
- HTTP redirects не следуются, cookies не сохраняются и не отправляются, auth/proxy из
  окружения не подхватываются; response headers фильтруются, HTML ограничен размером.
  Повторный GET после обрыва тоже не разрешён. Timeout/stop не отзывают уже выданный запрос.
- Сеанс принадлежит окну Jarvis; об эфемерности явно сказано до ввода. При закрытии этого
  окна вкладки и набранный текст удаляются. Пользовательский профиль браузера не подключается.
  Не вводить credentials в поля/URL; будущие OAuth adapters используют OS credential store.
- Audit исключает URL, page text, DOM, form contents, raw exceptions и tokens целиком.
  SUCCESS означает проверенное наблюдение, а не обещание бизнес-результата внешнего сервиса.
  Ответ поискового сайта с challenge не является доказательством найденных результатов.
