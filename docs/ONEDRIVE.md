# OneDrive и Excel: файлы и отчёты

Четвёртый коннектор фазы 2. Три чтения и одна запись, которая спрашивает.

## Подключение

OneDrive едет на том же аккаунте Microsoft, что и Outlook, но **на отдельном согласии**.

1. Вкладка «Outlook» → **Подключить / сменить аккаунт**, как обычно.
2. Там же → **Разрешить OneDrive**. Окно Microsoft для того же аккаунта: Jarvis просит
   `Files.ReadWrite`, и больше ничего.

Почему одно право на чтение и запись: у Excel нет более узкого. Чтобы прочитать ячейку
через Graph, уже нужен `Files.ReadWrite` — `Files.Read` хватает только поиску файлов.
Право широкое, поэтому оно спрашивается отдельно, а запись остаётся `CONFIRM`.

**Личный OneDrive не подойдёт.** Excel REST API обслуживает только рабочие и учебные
диски; на личном аккаунте файлы найдутся, а их содержимое — нет. Это ограничение
Microsoft, а не коннектора.

## Что он умеет

| Инструмент | Уровень | Что делает |
| --- | --- | --- |
| `onedrive.files` | `SAFE` | Найти файлы по названию; говорит, книга это Excel или нет |
| `onedrive.sheets` | `SAFE` | Листы книги: имя, позиция, скрыт ли |
| `onedrive.read` | `SAFE` | Диапазон листа; без адреса — использованный диапазон |
| `onedrive.write` | `CONFIRM` | Записать значения в диапазон |

Запись спрашивает. Книга в OneDrive обычно общая, прежнее содержимое ячейки после
перезаписи не вернуть, а отмены здесь нет — такого маршрута не существует. Опустить
до `ROUTINE` можно своей матрицей.

Сессия книги (`workbook-session-id`) не используется: по документации Microsoft запрос
без заголовка сессии **сохраняет** изменения. Сессия — решение о производительности,
а не то, что делает запись настоящей.

## Как проверяется запись

Записанный диапазон **перечитывается по тому же адресу**. Это настоящий второй взгляд,
а не отчёт сервиса о самом себе: у диапазона есть адрес, поэтому его можно спросить
заново — именно того, чего нельзя сделать с только что созданным блоком Notion или
отправленным сообщением Teams.

Сверка точная, с одним допущением: число сравнивается как число, потому что Excel хранит
`42` и `"42"` одинаково, как только в ячейке появилось значение. Всё остальное должно
вернуться символ в символ. Значит, строку, которую Excel решит переосмыслить — дату вроде
`01.09.2026`, превращаемую в порядковый номер, — проверка **завалит**, а не пропустит
молча. Это честный ответ: в книге лежит не то, что просили.

## Границы, которые стоит знать

- **Значения должны заполнять адрес ровно.** Если форма не сходится, Excel копирует одно
  значение по всему диапазону («CTRL+Enter»), то есть заливает ячейки, которых никто
  не трогал. Поэтому несовпадение отвергается до отправки.
- **Формул нет.** Ячейка держит текст или число; строка, начинающаяся с `=`, не
  принимается. Коннектор, принимающий формулы, позволял бы запланированному шагу считать
  в чужой книге — это другая поверхность.
- Имя листа проверяется по правилу самой Excel: до 31 символа, без `: \ / ? * [ ]`.
  Апостроф тоже запрещён — имя пишется внутри кавычек в адресе OData.
- Адрес — только A1-нотация (`A1`, `A1:D20`), без имени листа и без `$`.
- Запрос поиска и имя листа кодируются перед URL: кавычка не может закрыть сегмент,
  в котором живёт.
- Потолки: 50 строк × 20 колонок за одну запись, 255 символов в ячейке.
- Форматов, диаграмм, таблиц, добавления и удаления листов, загрузки, перемещения и
  удаления файлов нет. Не запрещено, а **отсутствует**: пять маршрутов, и никакой
  аргумент за них не выходит.
- В граф знаний попадает **файл**, а не его содержимое. Числа отчёта — содержимое по
  определению, и им нечего делать в промпте только потому, что файл однажды нашёлся.

## Официальные основания (проверены 18.09.2026)

- [GET /me/drive/root/search(q='…')](https://learn.microsoft.com/graph/api/driveitem-search)
  — делегированное `Files.Read`.
- [GET …/workbook/worksheets](https://learn.microsoft.com/graph/api/worksheet-list) —
  `Files.ReadWrite`.
- [GET …/worksheets/{имя}/usedRange](https://learn.microsoft.com/graph/api/worksheet-usedrange).
- [GET …/range(address='…')](https://learn.microsoft.com/graph/api/range-get).
- [PATCH …/range(address='…')](https://learn.microsoft.com/graph/api/range-update) —
  тело `{"values": [[…]]}`, ответ 200 с сохранённым диапазоном.
- [Работа с Excel в Graph](https://learn.microsoft.com/graph/api/resources/excel) —
  сессии, поведение без сессии, `null` и пустая строка в сетке значений, копирование
  одного значения по диапазону и запрет записи в неограниченный диапазон.

Две вещи прочитаны там, а не вспомнены: Excel REST API не обслуживает личный OneDrive,
и запрос без заголовка сессии всё равно сохраняет изменения.

## Проверка

Обычные тесты используют синтетические ответы, без аккаунта и без сети:
`tests/unit/test_onedrive.py`. **Живой OneDrive ещё не проверен** — нужен рабочий
аккаунт Microsoft, согласие на отдельную поверхность и книга на рабочем диске.
