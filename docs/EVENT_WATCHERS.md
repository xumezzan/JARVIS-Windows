# Фоновые подсказки DesktopService

Реализация по запросу 24 октября 2026; проверка на Mac завершена 25 октября.
`EventWatcher` принадлежит `DesktopService` и работает в его asyncio loop.
Наследуемая Qt-оболочка не получает наблюдателей. Новых служб, автозагрузки ОС,
записи микрофона, облачных вызовов и автоматической отправки писем нет.

## Включение

В Electron: **Настройки → Фоновые подсказки**. Три независимых переключателя:
буфер, почта, короткие подсказки системным голосом. Все выключены при запуске;
параметры действуют только в текущем сеансе. Для почты сначала явно подключите
Outlook в «Подключения». Включение фоновой почты разрешает реальные чтения
подключённого аккаунта, независимо от выбранной симуляции задач; это раскрыто
рядом с переключателем. Симуляция самих инструментов остаётся без адаптеров.

Выключенные наблюдатели не запускают loop и не читают свои источники. Включённый
loop проверяет доступность работы раз в секунду; читает буфер раз в 2 секунды,
`outlook.list` — раз в 300 секунд. Запись/распознавание/озвучивание, Runner и
ручные операции имеют приоритет. Новая команда отменяет и дожидается фонового
запроса; он не выполняется одновременно с foreground-инструментами.
**«Приостановить фоновые проверки»** в настройках или **Stop** отменяет текущую проверку, убирает подсказки и приостанавливает loop
до следующей команды/операции или изменения настроек. При закрытии loop
отменяется и дожидается завершения до закрытия аудита/сессии.

## Буфер обмена

Читает только plain text системного clipboard через main-process Electron API.
Renderer и модель не имеют API чтения буфера. Python запрашивает образец по
одноразовому ID; устаревшие ответы отклоняются. Ожидание образца — максимум
2 секунды. В приватный pipe попадает максимум 16 000 символов; большие значения
пропускаются целиком. Electron сначала выполняет native `readText`, поэтому
этот лимит не ограничивает выделение памяти внутри Electron при нативном чтении.
Никаких новых clipboard-зависимостей, shell, профилей или чтения selection clipboard.

Первая выборка — baseline, без уведомления. Локальные эвристики распознают:

- Стектрейсы от 300 символов, минимум 4 строки: Python Traceback или сочетание
  Error/Exception/panic с несколькими stack frames.
- Текст минимум с 250 буквами, где не менее 85% букв вне русского алфавита.
  Это эвристика относительно русского языка, а не точное определение языка;
  возможны ложные срабатывания на коде и других кириллических языках.

Текст не сохраняется в SQLite, аудите, истории/памяти задач и не попадает в state.
После проверки остаются только последние 32 SHA-256 fingerprints и generic offer.
Смена буфера убирает прежнюю подсказку; повторное содержимое не вызывает её снова
в пределах этого ограниченного кеша. Повторное копирование того же содержимого
между выборками неотличимо от отсутствия изменения.

**«Вставить в команду»** заново читает буфер и сверяет fingerprint. Затем до 3500
символов вставляются в composer; при обрезке есть предупреждение. Пользователь
проверяет текст и запускает команду обычным способом с нужным облачным согласием.
Включённый голосовой автозапуск не распространяется на эти подсказки.
После явного запуска действуют обычные настройки памяти задач.

## Outlook

Наблюдатель использует тот же зарегистрированный `outlook.list`, `PermissionEngine`,
проверку актуального аккаунта и durable audit. В список добавлены поля Graph
`importance` и `isRead`. Первая успешная выборка задаёт baseline; старая почта
не объявляется новой. Уведомления получают только ранее не встречавшиеся письма
с `importance=high`, `isRead=false` и `receivedDateTime` после начала наблюдения.
Некорректные metadata пропускаются отдельно, не скрывая соседнее валидное письмо.

Проверяются последние **10 входящих** по существующему контракту инструмента;
pagination/delta sync нет, при большом потоке письма могут быть пропущены.
Дедупликация хранит максимум 256 ID в RAM текущего аккаунта/сеанса. На смене
аккаунта, disconnect и выключении настройки кеш и почтовые подсказки очищаются.
Ошибки проверки не включают OAuth и не повторяются немедленно: следующий запрос
идёт по расписанию через 5 минут. Повторяющиеся ошибки видны в настройках.

Подсказка показывает тему и **точный адрес отправителя**. Кнопка «Создать черновик
этому адресату» явно выбирает показанный адрес. Backend заново выполняет
`outlook.read`, проверяет ID, отправителя, тему и текущий account/session, затем
`outlook.local_draft` через PermissionEngine. Результат — редактируемый шаблон
ответа с `Re:` только в RAM. Это не модельный содержательный ответ и не Graph
reply thread; Reply-To, reply-all, вложения и автоматические адресаты не выводятся.
Черновик загружается в форму Outlook для редактирования. Удалённое сохранение и
отправка идут через обычную панель; отправка сохраняет точный UI CONFIRM.

## Уведомления и голос

До трёх подсказок в RAM, TTL 5 минут. Clipboard-подсказки и озвучивание ограничены
одним событием в минуту; почтовые события во время cooldown показываются тихо.
HUD в углу остаётся display-only, click-through и не скрывает workbench/не получает
фокус. Cmd/Ctrl+Alt+J открывает основное окно. Мягкое двукратное мигание учитывает
`prefers-reduced-motion`. Действия доступны в основном окне.

Озвучивается только фиксированный русский вопрос, без тела письма, темы, адреса
и содержимого буфера. Используется системный TTS; облачный ElevenLabs и его
одноразовое согласие на итог не переиспользуются. Занятый голос не прерывается;
проверки возобновляются после его освобождения. Никакие события не дают approval,
облачного согласия, свежих planner observations или разрешения отправить письмо.

Календарный триггер не добавлен: в запросе не задан отдельный сценарий, а текущая
интеграция содержит только почту. Новые OAuth scopes и календарные операции не
предполагаются автоматически.

## Проверка

```sh
python -m pip install -e ".[dev]"
python -m pytest tests/unit/test_watchers.py tests/integration/test_event_watchers.py
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m jarvis --smoke-test
python -m build
node --test desktop/electron/clipboard.test.cjs desktop/electron/overlay.test.cjs
npm --prefix desktop run build
# POSIX QA: настоящий Electron, синтетический clipboard, временные данные:
JARVIS_PYTHON=/path/to/test-venv/bin/python npm --prefix desktop run qa:watchers
JARVIS_PYTHON=/path/to/test-venv/bin/python npm --prefix desktop run qa:overlay
```

Проверены local heuristics, off/baseline/TTL/dedup/cooldown, непрочитанная высокая
важность, смена аккаунта, stale clipboard/mail, одноразовый receipt, прерывание
зависшего Graph-запроса, отсутствие фоновых черновиков/автозапуска/записи текста,
fail-closed audit, локальный черновик без Graph POST. Native clipboard adapter
проверен с подставленным sync/async `readText`, без доступа к буферу пользователя.

Настоящий Electron прошёл fixture QA: HUD не крадёт фокус и не скрывает окно,
reduced motion выключает мигание, composer получает текст без автозапуска,
на 390px нет page/internal overflow, выключение останавливает наблюдателя.
Снимки и результаты: [watchers-verification.json](../desktop/qa/watchers-verification.json),
[настройки](../desktop/qa/watchers-settings.png), [orb](../desktop/qa/watchers-orb.png),
[390px](../desktop/qa/watchers-mobile.png). Шрифт Inter сохранён из пользовательского
референса; единственное предупреждение Impeccable detector относится к этому
существующему шрифту.

Windows clipboard, настоящий OAuth/важное письмо, системный звук и Windows E2E
не проверены. На Windows запустите полный `python -m pytest`, затем
`npm --prefix desktop start`; включите наблюдатели через UI, скопируйте тестовый
стектрейс и иностранный текст, дождитесь нового важного письма в выбранном тестовом
аккаунте (не менее 5 минут). Проверьте голос, отсутствие повторов, реальный corner
HUD/click-through, Stop, disconnect, черновик без отправки и выключение/закрытие.
Фикстуры на Mac не заменяют эти действия и не дают разрешения отправлять письма.
