# Сквозной контекст и procedural memory

Расширение по прямому запросу пользователя от 2026-10-24. Это отдельное исключение
из прежнего запрета автоматического сохранения команд в памяти этапа 7. Профиль
из 32 коротких меток и его явное редактирование не меняются.

## Как работает

`DesktopService` владеет `ConversationRingBuffer` и `ExperienceStore`. После реального
завершения `finished`, когда каждый инструмент вернул `SUCCESS`, сохраняются исходная
команда, фактическая сводка статусов, полный финальный Scratchpad, имена инструментов
и наблюдавшиеся HWND/URL/пути. Ошибки, отмены, timeout, лимит, отсутствие действий и
симуляции не записываются и не обучают рецепты. Промежуточные результаты, документы,
страницы, screenshots, аргументы действий, account/DOM/editor identities, версии файлов,
approval/capability и вложения автоматически не копируются.

Scratchpad снимается в `PlanResult` **до** очистки Runner; Runner остаётся одноразовым.
При следующем запуске история передаётся как отдельный `TaskMemoryContext`, а не как
`steps` или рабочие заметки новой задачи. Например, «тот же текст» можно связать с
прошлым `draft`; если текст не сохранён в команде/заметках или ссылка неоднозначна,
модель должна уточнить его. Получатель всегда определяется текущей командой/уточнениями.

После успешного маршрута из минимум трёх вызовов и двух разных инструментов строится
символический Playbook: поисковые слова команды и последовательность имён инструментов.
Scratchpad-вызовы исключаются, последовательные повторения screenshot/inspect/read
сжимаются. Аргументы, текст, selectors, координаты и старые цели не сохраняются в рецепте.
В SQLite используется таблица `playbooks`; одинаковое намерение заменяет прошлый рецепт.
Подбор локальный: совпадения первых пяти букв слов, Jaccard >= 0.45 и минимум два общих
слова, либо точное совпадение набора. Передаются максимум три лучших рецепта.
Это лексический подбор подсказок, не семантический поиск и не автоматическое воспроизведение.

`OpenAIProvider` получает `untrusted_task_memory` в пользовательском data-блоке.
История/рецепты не становятся системными инструкциями. Провайдер может сократить
повторную разведку, когда свежих структурированных наблюдений достаточно. При превышении
лимита 256 KiB удаляются целые самые старые записи истории с `omitted_recent`, без
обрезания текста заметок. Если даже текущий контекст не помещается, запрос завершается
`context_limit`, без сетевого вызова.

## Управление и ограничения

- Реализовано для Electron / `DesktopService`; Qt сохраняет прежний явный профиль.
  Контракт Runner поддерживает передачу истории, но Qt автоматически её не собирает.
- По текущему запросу запоминание включено по умолчанию в сеансе Desktop. В разделе
  **Память → Недавние задачи и рецепты** его можно выключить перед чувствительной задачей.
  Выключение прекращает сбор/использование и оставляет прежние записи для просмотра/удаления.
  Настройка сеансовая: при новом запуске снова включена. Голосовые команды подчиняются
  тому же переключателю; это явно разрешённое данным запросом сохранение команды.
- Локально используются последние пять задач, каждая до 64 KiB, Scratchpad до 32 KiB.
  Срок задач — 30 минут от завершения, рецептов — 30 дней, максимум 32. История переживает
  перезапуск только в пределах срока. RAM очищается при shutdown. SQLite очищает истёкшие
  записи при следующем чтении/записи; при закрытом приложении нет фонового удаления.
- Таблицы `recent_tasks` и `playbooks` находятся в существующем `memory.sqlite3`, независимо
  от таблицы `profile`. UI позволяет раскрыть записи, удалить каждую отдельно и очистить
  задачи/рецепты вместе. Удаление задачи не удаляет отдельный рецепт; для него есть своя кнопка.
- SQLite: atomic transaction, `secure_delete=ON`, DELETE journal, busy timeout 1 секунда,
  размер общей базы до 4 MiB; I/O в `asyncio.to_thread`. Ошибка памяти не меняет фактический
  итог действия: показывается уведомление, устаревший RAM-контекст не используется.
  Это не hard deadline для зависшей файловой системы. Дисковая копия не шифруется.
- Удаляются известные credential/approval-поля и поля с явными признаками секретов;
  email-адреса маскируются, URL userinfo/query/fragment исключаются. Это защитный фильтр,
  **не универсальный DLP**: произвольный личный текст может остаться в команде/Scratchpad.
  Секреты вводятся только в существующие credential adapters, не в команды и заметки.
- Для OpenAI есть отдельный `conversation_consent` на одну задачу. Без него исторический
  контекст не передаётся, даже при разрешении текущих наблюдений или выбранных меток.
  Галочка сбрасывается после запуска, смены модели/провайдера и изменения истории.
  Голосовой автозапуск не выдаёт ни это согласие, ни cloud consent, ни action approval.
- Старые HWND/URL/пути только помогают найти цель. `Runner._observed_target` учитывает
  исключительно успешные `steps` **текущей** задачи. Версия файла для overwrite, цель окна,
  элемент страницы и аккаунт заново наблюдаются; exact UI CONFIRM и durable audit сохранены.
  Кэш не расширяет filesystem roots, BrowserMode или разрешения. Автоповторов эффектов нет.

Ускорение в три раза не измерено и не гарантируется. Его проверяют на одинаковой задаче
и целевом Windows-устройстве: холодный/повторный сценарии, число tool/screenshot вызовов,
wall time, одинаковые результаты и сохранённые проверки. Live OpenAI, голосовое
оборудование и Windows данным локальным расширением не верифицируются.

## Проверка

Из изолированного окружения с editable `.[dev]`:

```sh
python -m pytest tests/unit/test_task_memory.py tests/integration/test_conversation_memory.py
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m jarvis --smoke-test
python -m build
npm --prefix desktop run build
npm --prefix desktop run qa:electron
```

На Windows 11 с его активным окружением выполнить те же команды (`.venv\Scripts\python.exe`
вместо `python`) и проверить повторную голосовую задачу в реальном окне: согласие
на передачу истории, свежие наблюдения, точное подтверждение отправки/перезаписи,
просмотр/удаление записей, перезапуск и отказ от использования старых целей.

Локальные результаты 2026-10-24, macOS / Python 3.12, чистое окружение
`/tmp/jarvis-task-memory-qa-20261024` с editable `.[dev,voice]` и Pillow:

- Новые unit/integration: **17 passed**; весь набор: **904 passed, 5 skipped**.
  Пропущены opt-in live model, voice и Windows acceptance.
- Ruff check/format, strict mypy, `git diff --check`: успешно.
- Qt offscreen GUI smoke, Python sdist/wheel, TypeScript/Vite build: успешно.
- Основной `qa:electron`: настоящий локальный `system.info`, simulation/cancel,
  сохранённые границы renderer/approval/voice, отсутствие overflow — успешно.
- Новые элементы памяти проверены в настоящем Electron с помеченной синтетической
  SQLite-записью: восстановление и просмотр полного текста, длинная строка на 1536/390px,
  отключение, удаление рецепта и очистка. Это проверка UI/хранилища, не Windows UIA.
- Первоначальный прогон в старом `.venv-reference` остановился из-за неработающего
  editable `.pth` и отсутствующего Qt platform plugin. Для итоговых проверок создано
  чистое окружение; ослабления worker isolation или подмены успешных статусов не было.
