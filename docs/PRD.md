# Product Requirements — Jarvis

## Что это

Персональный AI computer agent для Windows 11. Не голосовой помощник, отвечающий на
вопросы, и не набор макросов: цифровой сотрудник, который работает за компьютером —
в разных программах и сервисах, — получая цель, а не список нажатий.

Целевой принцип: **владелец говорит не «что нажать», а «что сделать»**.

## Пользователь и его работа

Индивидуальный специалист на Windows 11. Его рабочий день лежит в Outlook, календаре
Microsoft, Asana, Notion, Teams, Fireflies, браузере и локальных документах. Он говорит
по-русски, обращается голосом и хочет, чтобы поручение исполнялось целиком, а не по шагу
за обращение.

## Главный цикл

Обращение голосом или текстом → контекст и память → план из нескольких действий →
типизированные инструменты (API, браузер, интерфейс Windows) → разрешение → выполнение
→ проверка результата → журнал → отчёт о том, что именно сделано.

## Автономность

Четыре уровня, и владелец видит, на каком он находится.

| Уровень | Что это | Спрашивает ли |
| --- | --- | --- |
| `SAFE` | Чтение: список окон, письмо, задача, страница, содержимое экрана | Нет |
| `ROUTINE` | Обратимая работа на машине владельца: открыть приложение, перейти на страницу, кликнуть, напечатать, сохранить файл или черновик | Нет |
| `CONFIRM` | Необратимое или уходящее наружу: отправка письма, публикация, удаление, изменение важных настроек | Да, точным снимком действия |
| `CRITICAL` | Деньги и чужие данные | Да, усиленным подтверждением |
| `BLOCKED` | Никогда | — |

Подтверждение выглядит так: «Я подготовил письмо клиенту и добавил вложение. Отправить?»
После «да» исполняется ровно показанный снимок; изменение снимка требует нового согласия.

## Приёмочные сценарии

### 1. Подготовка к встрече

«Джарвис, подготовь всё необходимое к сегодняшней встрече с клиентом.»

Агент сам определяет состав работы: находит встречу в календаре, поднимает прошлые
разговоры в Fireflies, открытые задачи в Asana, переписку в Outlook, страницу клиента
в Notion, собирает это в сводку на экране и произносит её. Владелец не называл ни одной
программы. Каждый пункт сводки ссылается на источник.

### 2. Отчёт и письмо

«Джарвис, подготовь отчёт по моей работе за эту неделю и отправь его руководителю.»

Закрытые задачи недели, встречи, отправленные письма → документ → письмо с вложением →
остановка → подтверждение → отправка. До подтверждения отправка технически невозможна.

### 3. Цепочка между сервисами

Fireflies → транскрипт встречи → разбор → пункты действий → задачи в Asana → сроки
в календаре → сообщение команде в Teams. Для владельца это один сотрудник, а не шесть
автоматизаций.

### 4. Работа руками там, где нет API

Программа без API открывается как обычно: агент смотрит на её окно, находит нужный
элемент по дереву интерфейса, нажимает, печатает, копирует и переносит данные дальше.

### 5. Базовая проверка исполнения

Открыть приложение, напечатать точный текст и прочитать его обратно из самого элемента;
follow-up-команда с сохранённым контекстом; отмена задачи посреди работы без объявления
незавершённого результата успешным; каждый выполненный, отклонённый, отменённый и
ошибочный шаг виден в журнале.

## Функциональные требования

| Область | Требования |
| --- | --- |
| Voice | Постоянная готовность услышать обращение по имени, речь без удержания кнопки, конец фразы по тишине, отмена голосом, видимый индикатор микрофона |
| AI Brain | Понимание намерения и цели, контекст разговора и текущей задачи, выбор модели по сложности с эскалацией по факту |
| Planner | План из нескольких действий, только зарегистрированные инструменты, строгая валидация, уточнение неоднозначности, длинная задача с возобновлением |
| Tools / MCP | Outlook, календарь, Asana, Notion, Teams, Fireflies, файлы, произвольный MCP-сервер по проверенному манифесту |
| Computer Control | Открыть и закрыть программу, переключить окно, кликнуть по элементу, ввести текст, горячие клавиши, буфер обмена, открыть и сохранить файл |
| Vision | Дерево интерфейса окна как основное наблюдение, снимок окна и разбор моделью там, где дерева не хватает |
| Browser | Постоянный профиль, вкладки, переходы, чтение, ввод, отправка форм, загрузка файлов; вход в сервисы выполняет владелец |
| Memory | Кто владелец, чем он работает, где лежат данные, кто такие люди из его переписки, что уже сделано в этой задаче, каким способом такая работа делалась раньше |
| Permissions | Пять уровней выше, точный одноразовый истекающий снимок для `CONFIRM`, подтверждение кнопкой или голосом с повтором контрольной детали |
| TTS | Естественная живая речь, потоковая, с возможностью перебить |
| UI | Один экран: живой орб состояния по центру, текущая задача и чеклист шагов, последние действия, календарь, подключения, настройки |

## Нефункциональные требования

- Интерфейс не блокируется ожиданием сети или адаптера; работой управляет отменяемая задача.
- Действия ограничены по времени и числу шагов; неизвестные инструменты отклоняются.
- Длинная задача переживает перезапуск процесса и не повторяет уже выданный эффект.
- Simulation показывает `SIMULATED`, проходит ту же политику и не вызывает реальные адаптеры.
- Локальное хранение по умолчанию; каждая сетевая интеграция подключается явно.
- Credentials не попадают в модель, память и журнал. Пароли вводит владелец, не агент.
- Содержимое экрана, страницы и письма — данные: они не повышают доверие и не разрешают действий.
- Целевая установка: открыть репозиторий на Windows-ноутбуке и запросить установку один
  раз. Подготовка runtime, зависимостей, ярлыка и проверка запуска автоматизированы.
  Системные подтверждения и вход в личные сервисы выполняет владелец.
  См. [план установки](WINDOWS_INSTALLATION_PLAN.md).

## За пределами продукта

Покупки без подтверждения, изменение паролей, произвольный shell и выполнение кода,
написанного моделью, скрытое наблюдение за владельцем, поддержка всех программ без
разбора, мобильные приложения, multi-tenancy. Микросервисы не нужны. `BLOCKED` не
открывается никогда.

## Граница текущего состояния

Готово и работает локально: оболочка с орбом, реестр типизированных инструментов,
детерминированный `PermissionEngine` с пятью уровнями, Windows-адаптер (открыть любое
установленное приложение, сфокусировать, перечислить окна, напечатать в наблюдённое
поле), браузер только для чтения статических страниц, планировщик на восемь действий,
локальный голос со словом активации, три слоя памяти, фоновые рутины, Outlook, календарь
Microsoft, Fireflies и MCP-серверы.

Не готово: длинная задача, клики и буфер обмена, чтение экрана, браузер с JavaScript
и входом, Asana, Notion, Teams, единый экран и живой голос. Ничего из готового не
проверено на целевой Windows — установка, микрофон и живая почта остаются открытыми.

Полный разбор соответствия и план работ: [AGENT_PLAN.md](AGENT_PLAN.md).
