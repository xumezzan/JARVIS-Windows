сохраняется: сначала native-приёмка и упаковка этапа 9, затем расширение.

## Пользователь и полный продукт

JARVIS — персональный AI-помощник для Windows с текстом и голосом. Он получает только
разрешённый рабочий контекст, строит ограниченный план, действует зарегистрированными
инструментами, проверяет результат и сообщает фактические исходы.

Полная версия объединяет Windows/browser control, рабочие сервисы, личную память,
знания компании, многошаговые процессы, явно включаемые фоновые процедуры,
специализированные роли агентов, обучение по демонстрациям и простой мастер настройки.
Это направление развития, а не описание текущих возможностей или обещание поддержки
любой программы. Архитектура остаётся одним локальным приложением без лишних сервисов.

Главный цикл: запрос → разрешённый контекст → ограниченный план → строгий tool →
PermissionEngine → точное согласие, если нужно → действие → проверка → аудит → отчёт.

## Текущий MVP и его завершение

Этапы 0–8 реализованы локально; переносимая часть этапа 9 подготовлена.
**MVP ещё не принят:** Windows 11 x64, чистая установка, полный E2E, реальное голосовое
оборудование, live Outlook OAuth/почта и live модель остаются непроверенными.
Успешные fixtures, Mac GUI и сборки этого не заменяют. ElevenLabs Free — уже добавленная
опция, её живой API/звук также pending; опция не заменяет локальную голосовую приёмку.

| Область | Фактическая граница MVP |
| --- | --- |

| Windows | Allowlisted Notepad/Chrome/VS Code: открыть, перечислить, сфокусировать. CONFIRM-ввод только в наблюдённый пустой Notepad, точная идентичность окна/редактора/вкладки и UIA read-back. |
| Browser | Собственный анонимный Chromium, статический HTML, JavaScript выключен, browser context offline; точечный проверяемый транспорт документов. SAFE read/tabs; переходы, поиск, click/type/close — CONFIRM. Production POST и пользовательский профиль запрещены. |
| Planner | Offline учебные рецепты или opt-in OpenAI; один tool на шаг, по умолчанию 30 действий / 3 уточнения / 30 секунд provider / 300 секунд задача. ### Неизменённая приёмка MVP, этап 9

Полная матрица и команды: [WINDOWS_ACCEPTANCE.md](WINDOWS_ACCEPTANCE.md).

1. Установить на чистой Windows 11 x64 по одному запросу, открыть настоящее окно и ярлык.
2. В Planner выполнить «Открой Chrome и найди OpenAI»: увидеть Chrome и фактическую
   поисковую выдачу в отдельном принадлежащем JARVIS Chromium. Challenge/пустая страница
   не проходят. Поиск именно в пользовательском Chrome — открытый вопрос, не повод
   ослабить текущую browser boundary.
3. «Открой Блокнот и напиши Jarvis test successful»: до Approve пустой редактор,
   после — точный текст с UIA read-back. Проверить изменение вкладки и отмену.
4. Выполнить follow-up с явно выбранной меткой приложения и свежим наблюдением цели;
   неоднозначный контакт требует уточнения.
5. Выполнить русский voice-сценарий с настоящим удержанием, review и submit. Проверить
   неверную речь, Stop, потерю фокуса и закрытие; голос не подтверждает действия.
6. Свой Outlook test account/recipient: показать сервис, аккаунт, To/Cc/Bcc, тему, тело,
   имя/размер/SHA-256/ID вложений, связанных с точными RAM bytes; remote draft/send невозможны до точного одноразового UI approval.
   Проверить read-back draft; send acceptance и доставку записать раздельно.
7. Проверить audit выполненных, отклонённых, отменённых, ошибочных и неопределённых шагов;
   expiry/reuse, prompt injection, сеть и emergency stop. Уже выданный эффект не откатывается.
8. Пройти native quality gates и packaging, зафиксировать проверенные Windows зависимости
   и повторить чистую установку. Непройденный обязательный gate оставляет MVP открытым.

Завершённый MVP даст ограниченный Windows-помощник с текстом, локальным голосом,
проверяемыми Windows/browser-действиями, управляемыми метками и Outlook. Он не включает
весь будущий каталог, фоновые задачи, визуальное управление или знания всей компании.

## Язык и локализация — обязательная цель следующей версии

Английский — основной язык продукта. Этап 10 вводит локализацию после сохранённого
этапа 9; этап 12 использует её в onboarding. Текущий русский UI не объявляется английским,
а историческая русская приёмка MVP не переписывается как уже выполненная EN/RU приёмка.

- Первый запуск, Welcome, инструкции, UI, статусы, ошибки, уведомления, диалоги
  подтверждения и help по умолчанию английские; разговор и spoken response тоже English.
- На первом экране сразу виден English / Русский. Переключение применяется к оставшейся
  настройке немедленно. После настройки: Settings → Language, без переустановки,
  потери данных и повторного подключения аккаунтов.
- Полная русская локализация включает onboarding, consent/approval, ошибки, help,
  системные сообщения и голос. Язык разговора независим от языка UI: EN UI + RU запросы
  и RU UI + EN запросы входят в приёмку, и текстом, и настоящим голосом.
- Язык письма, комментария или документа задают запрос пользователя и подтверждённый
  контекст адресата. При конфликте — уточнение. UI locale не переписывает исходный текст.
- Смена языка не переводит документы, названия аккаунтов или содержимое ожидающего
  approval. Снимок остаётся побайтно тем же; любое редактирование действия аннулирует
  approval. Безопасное представление и доступность полного preview проверяются в обоих языках.
- Даты, время и числа отображаются по выбранным locale/time zone. Точное время действия
  связывает зону/смещение, включая DST; неоднозначная дата требует уточнения.
- Структура переводов, plural forms, форматирования и голосовых ресурсов позволяет
  добавлять языки без переделки интерфейса. Отсутствующий голос виден как setup required,
  а не молчаливый переход к облаку или ложная готовность.

## Будущие сценарии и границы

### Рабочий экран, Windows и браузер

Открывать и переключать приложения, окна, вкладки; поддержать несколько мониторов;
сначала official API, затем structured browser, Windows UI Automation и только затем
отдельно ограниченную visual interaction. Скриншоты/OCR/visual model применяются при
недостаточности структурированного доступа и с явным разрешением на область/передачу.
Для кликов, ввода, форм и контролируемого переноса между приложениями нужны наблюдаемая
цель, точный payload и проверка каждого значимого результата. При изменении интерфейса
или неоднозначности — stop/re-observe/clarify, без слепого coordinate replay.
Динамические авторизованные сайты (22), дополнительные Windows inputs/transfer (23)
и visual control (24) не расширяют действующие инструменты до собственной приёмки.

### Подключаемые сервисы

Все запрошенные сервисы, операции, scopes, типы аккаунтов, источники и ограничения:
[INTEGRATIONS.md](INTEGRATIONS.md). Каталог открыт для новых адаптеров через
[общий контракт](INTEGRATION_CONTRACT.md), доверенную регистрацию и PermissionEngine.
Чтение, локальная подготовка и внешнее действие — отдельные capabilities. Подключение,
приложение на компьютере, подписка или логотип не означают доступ API либо согласие на send.

### Email → задачи → календарь

«Проверь почту, выдели важное, подготовь ответы на обычные письма, создай Asana-задачи
по поручениям, предложи встречи и скажи, что осталось».
Помощник уточняет критерий важности, период, аккаунты, исполнителей и адресатов;
сохраняет ссылки на источники, показывает каждый внешний action, исполняет только
разрешённые шаги и сообщает completed/denied/error/uncertain/unfinished.
Ограничиваются шаги, wall time, provider calls/tokens и расходы. Отмена запрещает новые
шаги; общий plan finish не доказывает business outcome. Дубликаты между шагами/агентами
и после потери сетевого ответа блокируются, неопределённые writes не повторяются.

### Личная память и знания компании

Личная память хранит явно выбранные предпочтения и процессы. Отдельная company KB —
структуру компании, сотрудников, клиентов, проекты, правила и стандартные ответы из
разрешённых источников. Каждая запись имеет provenance, дату обновления, владельца,
границы user/organization/account, срок актуальности и политику хранения.
Нужны view/correct/delete/disable, разрешение конфликтов и устаревания. Автоматического
поглощения всех доступных документов нет. Контакты уточняются; секреты не являются памятью.
Полное и безошибочное понимание компании без источников не обещается.

### Утренний обзор и фоновые процедуры

После MVP, только с enablement: расписание или явно разрешённые события, выбранные
email/calendar/Asana/QuickBooks/social/Omadli источники, time zone, quiet hours,
уведомления, лимиты, disable. Показывать срочные письма, встречи, просроченные задачи,
новых клиентов, комментарии и неоплаченные счета только там, где данные доступны.
Недоступный источник означает missing coverage, а не отсутствие событий.
Read, prepare и external changes имеют раздельные полномочия. По умолчанию нет фоновых
send/post; будущие standing rules требуют отдельного узкого решения. Компьютер выключен —
локальный запуск не обещается; внешний исполнитель требует отдельной архитектуры.

### Роли и обучение по демонстрации

Email/calendar/tasks/social/finance/company knowledge/browser/Windows роли могут помогать
анализировать сложный контекст. Для простого чтения/записи достаточно tool или обычного
workflow. Один orchestrator владеет общими лимитами, очередью эффектов и итоговым audit;
агенты видят минимум данных и не выдают approval друг другу.

Демонстрация: явный start → видимый indicator и согласованная область → редактируемый
workflow с параметрами, условиями и проверками → review → trial run → разрешённый повтор.
Исключать secrets/лишние персональные данные, привязывать к элементам и состоянию,
останавливаться при изменениях, поддерживать версии/edit/delete. Approval не записывается
как повторяемый шаг. Надёжное освоение любой работы с одной демонстрации не обещается.

### Первый запуск

Отдельный этап 12: Welcome → объяснение → Find my apps → выбор модулей → официальное
подключение/подготовка → личные настройки → readiness и безопасная первая задача.
Подробный экранный контракт: [ONBOARDING.md](ONBOARDING.md). Обнаружение не читает рабочее
содержимое; OAuth/MFA/consent делает пользователь. Нельзя автоматически включать платные
сервисы или устанавливать компоненты без согласия на конкретную установку.

## Общие ограничения и исключения

- Все будущие tools, роли, workflows и onboarding используют строгие схемы и engine;
  untrusted content не изменяет policy, mode, registry, scopes или approvals.
- Exact expiring single-use approval связывает сервис/account/target/content/attachments;
  изменение или отмена инвалидируют его. Connection consent не заменяет action approval.
- CRITICAL выключен в MVP. Финансовые изменения, infrastructure/admin writes, social
  DMs/publishing и video distribution отделены от read/обычных comments в этапах 29–32.
  Переводы денег, раскрытие secrets, отключение защиты и скрытое наблюдение запрещены.
- Нет скрытой записи микрофона/экрана, произвольного model code/shell, универсального
  управления любой программой, обхода ограничений сервиса или микросервисов без причины.
- Simulation проходит policy, но никогда не вызывает tool adapters. Уже существующие
  отдельные cloud-provider/TTS opt-in disclosures сохраняются даже при simulation tools.
- Данные и credentials локальны по умолчанию; cloud processing требует отдельного
  раскрытия и согласия. OS credential store остаётся обязательным; 1Password не заменяет
  его автоматически и не отдаёт vault contents модели.
