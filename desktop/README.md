# Jarvis Desktop

Основное приложение: Electron + React + Vite + TypeScript + Tailwind + lucide-react + framer-motion. Frameless окно 1536×1024, кастомный titlebar, локальные шрифты и процедурная синяя сфера. Визуальная основа — [референс](../reference/ui.png), палитра и размеры — `src/tokens.css`.

Приложение начинает работу с пустой историей. Команда, шаги, результат, состояние Outlook и голоса приходят от Python-движка. Демонстрационных встреч, профиля, подключений и таймера успешного выполнения нет.

## Запуск

Из корня репозитория, с установленным Node.js, поддерживаемым Vite:

```sh
npm --prefix desktop ci
npm --prefix desktop start
```

Первый запуск проверяет Python 3.12+ и автоматически устанавливает зависимости движка в отдельное окружение JarvisDesktop в каталоге данных пользователя. На Mac нужен установленный Python 3.12+. На Windows сначала используется штатный `scripts/windows/Install-Jarvis.cmd`, который подготавливает Python без ручного pip. Сам Windows-установщик пока запускает прежнюю Python-оболочку; поставка Electron через этот установщик и Windows-приёмка ещё не выполнены.

`npm --prefix desktop run setup` отдельно подготавливает движок. `JARVIS_PYTHON` позволяет выбрать уже установленное окружение. `npm --prefix desktop run desktop` запускает режим разработки с собственным Vite на 127.0.0.1:5173. `npm --prefix desktop run dev` открывает только renderer для проверки в браузере: без Electron команды честно недоступны.

## Использование

- «Ассистент»: ввод команды, явный выбор симуляции или выполнения, реальные шаги, результат, остановка. Для локальной проверки в режиме выполнения введите `проверь систему`: движок прочитает ОС, архитектуру, число процессоров и свободное место через PermissionEngine.
- «Действия»: фактическая история текущего сеанса, максимум 20 записей. После закрытия она очищается.
- «Инструменты»: зарегистрированные инструменты; Windows-инструменты требуют Windows.
- «Подключения», «Память», «Настройки»: встроенные React-разделы; работают через headless JSONL-сервис. Поддерживается существующий Outlook; Teams, календарь и Asana не выдаются за реализованные интеграции.
- Запись начинается при удержании кнопки микрофона прямо в Electron (мышь или пробел). Vosk загружается заранее в постоянном AudioHost. Нужны локальная Vosk-модель и настройка устройств; обычный запуск не скачивает модель.
- Точные подтверждения и согласие на облако показаны в React. Только доверенный жест в изолированном preload передаёт ответ на конкретный approval; токены выдаёт Python. OAuth открывается системным браузером. Секреты хранятся в OS credential store.

Модель и Outlook требуют настройки пользователем. Облачный провайдер получает команду только после отдельного видимого согласия. Без настроенного облака работают ограниченные офлайн-рецепты; универсальное понимание произвольных запросов не имитируется.

## Проверки

```sh
npm --prefix desktop run build
npm --prefix desktop run qa:electron
```

Playwright запускает реальное Electron-окно и Python-процесс с временным каталогом данных. Проверяет чистый старт, системную команду, симуляцию, уточнение/отмену, навигацию, настройки голоса без записи, изоляцию renderer, размеры и закрытие. Итоги и снимки находятся в `qa/`. Проверки не входят в аккаунты, не обращаются к облачной модели и не записывают микрофон.

[Архитектура и результаты](../docs/DESKTOP_APPLICATION.md) · [Дизайн](DESIGN.md) · [Продуктовые границы](PRODUCT.md).

## Голосовой тракт и headless-сервис (24 октября 2026)

В настройках доступен выключенный по умолчанию «Голосовой автозапуск». При confidence
от 0,75 команда запускается и системный голос отвечает «Принял, выполняю». Для OpenAI
нужно отдельное согласие на одну проверенную команду; CONFIRM-действия всегда требуют
точного подтверждения. Краткий отчёт модели до 300 символов озвучивается локально при
включённом озвучивании. Для ElevenLabs сначала покажите итог в настройках, выберите
голос, разрешите одну озвучку и нажмите «Озвучить итог».

`npm --prefix desktop run qa:voice` проверяет реальные жесты Electron с изолированным
fixture-процессом Python и искусственным аудио, без микрофона и облака. На macOS/Linux
задайте `JARVIS_PYTHON` в окружение тестового venv. Это не аппаратная voice-приёмка.
Подробнее: [голосовой runtime](../docs/VOICE_RUNTIME.md).

## Плавающий HUD

Реальная задача автоматически показывает HUD 320×110 поверх других окон, пропуская клики.
Подтверждения возвращают полное окно. `Ctrl+Alt+J` открывает его вручную, `Ctrl+Alt+Esc`
останавливает задачу; на Mac — Cmd вместо Ctrl. Перед кликом видимая цель подсвечивается
на 300 мс. Для проверки HUD без Windows-кликов:

```sh
JARVIS_PYTHON=/path/to/test-venv/bin/python npm --prefix desktop run qa:overlay
```

[Поведение, безопасность и Windows-проверка](../docs/DESKTOP_APPLICATION.md#hud-и-подсветка-цели-24-октября-2026).

## Файлы и вычисления

Планировщику доступны `fs.search`, `fs.read_document`, `fs.write_file` и
`python.sandbox_eval`. Рабочие папки ограничены настройками запуска; новая запись без
подтверждения разрешена только в `workspace`. Перезапись требует прочитанной версии файла
и точного подтверждения. Вычислитель исполняет ограниченное подмножество Python, без
file/network/OS API. PDF-сканы требуют отдельного OCR; XLSX не поддерживается.
[Конфигурация, примеры и границы](../docs/FILESYSTEM_TOOLS.md).
